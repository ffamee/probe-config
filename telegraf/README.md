# Telegraf Plugins Documentation

## 📡 Wireless Plugin

### Overview
เก็บข้อมูลสถานะและคุณภาพของการเชื่อมต่อเครือข่ายไร้สาย (Wi-Fi) บน Linux โดยอ่านค่าจาก `/proc/net/wireless`

**Official Documentation:** https://docs.influxdata.com/telegraf/v1/input-plugins/wireless/

---

### 🎯 Metrics ที่เก็บ

#### **Tags**
- `interface` - ชื่อของ Network Interface Card (เช่น wlan0, wlp2s0)

#### **Fields - คุณภาพสัญญาณ (Signal Quality)**

| Field | หน่วย | คำอธิบาย | การตีความ |
|-------|------|----------|-----------|
| **`link`** | score | คุณภาพโดยรวมของการรับสัญญาณ | ยิ่งสูงยิ่งดี - การเชื่อมต่อเสถียร |
| **`level`** | dBm | ความแรงสัญญาณ (RSSI) | -30 ถึง -50: ดีเยี่ยม<br>-60 ถึง -70: ดี<br>-80 ลงไป: อ่อน |
| **`noise`** | dBm | ระดับสัญญาณรบกวน | ยิ่งต่ำ (ติดลบมาก) ยิ่งดี<br>พื้นที่เงียบสงบ ไม่มีคลื่นแทรก |
| `status` | code | สถานะภายในของอุปกรณ์ | ใช้สำหรับ Debug เชิงลึก |

> 💡 **Tips:** คำนวณ SNR (Signal-to-Noise Ratio) = Level - Noise
> ค่าห่างกันมาก = สัญญาณชัดเจน

#### **Fields - Error Counters**

| Field | คำอธิบาย | สาเหตุ/ผลกระทบ |
|-------|----------|----------------|
| `nwid` | แพ็กเก็ตจาก Network อื่น | พื้นที่มี Wi-Fi หนาแน่น "ได้ยิน" สัญญาณจากเครือข่ายอื่น |
| `crypt` | ถอดรหัสไม่ได้ | รหัสผ่านผิด, ปัญหา WEP/WPA หรือ Driver |
| `frag` | แพ็กเก็ตที่ถูก Fragment | ถ้าค่าสูง = สัญญาณรบกวนมากจนต้องหั่นข้อมูลเป็นชิ้นเล็ก |
| **`retry`** | ส่งข้อมูลซ้ำ | **สำคัญ!** ค่าสูง = ระยะห่างไกล/สัญญาณรบกวนสูง<br>ทำให้เน็ตช้าและกระตุก |
| `misc` | ข้อผิดพลาดอื่นๆ | เช่น Buffer เต็ม |
| **`missed_beacon`** | ไม่ได้รับสัญญาณ Beacon | **เตือน!** Wi-Fi กำลังจะหลุด หรือ Roaming ไม่เสถียร |

> ⚠️ **หมายเหตุ:** Counter เหล่านี้จะนับเพิ่มขึ้นเรื่อยๆ หากเพิ่มเร็วผิดปกติ = มีปัญหา

---

### 🔍 ค่าสำคัญที่ต้องโฟกัส

#### **1. Signal Level (level)**
- ตัวบอกความแรงสัญญาณพื้นฐาน
- ถ้าต่ำกว่า -70 dBm ต้องระวังคุณภาพการเชื่อมต่อ

#### **2. Retry Count (retry)**
- บ่งชี้ปัญหาคุณภาพสัญญาณโดยตรง
- ส่งผลต่อความเร็วและ latency ที่ผู้ใช้รู้สึกได้

#### **3. Missed Beacon (missed_beacon)**
- สัญญาณเตือนก่อนการ disconnect
- ควร monitor ใกล้ชิดเพื่อป้องกันการหลุดของ connection

#### **4. Signal-to-Noise Ratio (SNR)**
- คำนวณจาก level - noise
- บอกคุณภาพสัญญาณที่แท้จริงมากกว่า level เพียงอย่างเดียว

---

### 📊 Use Cases
- **Network Monitoring**: ติดตามคุณภาพ Wi-Fi แบบ real-time
- **Troubleshooting**: วินิจฉัยปัญหาการเชื่อมต่อที่ไม่เสถียร
- **Capacity Planning**: วิเคราะห์ coverage และ interference
- **SLA Monitoring**: รับประกันคุณภาพสัญญาณตามมาตรฐาน

## 🌐 Internet Speed Plugin

### Overview
วัดความเร็วอินเทอร์เน็ตและคุณภาพการเชื่อมต่อ (Download/Upload speed, Latency, Jitter, Packet Loss) โดยใช้บริการ [speedtest.net](https://www.speedtest.net/)

**Official Documentation:** https://docs.influxdata.com/telegraf/v1/input-plugins/internet_speed/

> ⚠️ **คำเตือนสำคัญ:** Plugin นี้ดาวน์โหลดข้อมูลหลาย MB ทุกครั้งที่ทำงาน ต้องตั้งค่า `interval` ให้สูง

---

### ⚙️ Configuration ที่สำคัญ

```toml
[[inputs.internet_speed]]
  # ⚠️ สำคัญที่สุด: อย่าตั้งต่ำกว่า 30 นาที!
  interval = "60m"  # แนะนำ 1 ชั่วโมง หรือ 4 ชั่วโมง

  # เปิดถ้าเครื่องแรมน้อย (เช่น Raspberry Pi)
  memory_saving_mode = false

  # แนะนำใช้ "multi" เพื่อความแม่นยำและวัด packet_loss
  test_mode = "multi"  # "single" หรือ "multi"

  # เลือก/กรอง Server ตามต้องการ
  # server_id_exclude = []
  # server_id_include = []
```

#### **การเลือก Test Mode**

| Mode | ข้อดี | ข้อเสีย | Packet Loss |
|------|------|---------|-------------|
| **single** | ใช้ทรัพยากรน้อย | อาจได้ความเร็วไม่เต็มที่ | อาจวัดไม่ได้ (return -1) |
| **multi** ⭐ | ได้ค่าแม่นยำที่สุด<br>เหมือนเทสบนเว็บ | กิน CPU/RAM มากกว่า | วัดได้แม่นยำ |

> 💡 **ทำไมต้องระวัง Interval?**
> หาก interval = 10s (default), Plugin จะดาวน์โหลดข้อมูลทุก 10 วินาที = **เน็ตจะช้ามากและโควต้าหมดเร็ว**

---

### 🎯 Metrics ที่เก็บ

#### **Tags**
- `source` - ชื่อเซิร์ฟเวอร์ที่ใช้ทดสอบ (เช่น speedtest02.z4internet.com:8080)
- `server_id` - ID ของเซิร์ฟเวอร์ทดสอบ
- `test_mode` - โหมดการทดสอบที่ใช้ (single/multi)

#### **Fields - ความเร็วและคุณภาพ**

| Field | หน่วย | คำอธิบาย | การตีความ |
|-------|------|----------|-----------|
| **`download`** | Mbps | ความเร็วดาวน์โหลด | **ยิ่งสูงยิ่งดี** - บอกความเร็วรับข้อมูล |
| **`upload`** | Mbps | ความเร็วอัปโหลด | **ยิ่งสูงยิ่งดี** - บอกความเร็วส่งข้อมูล |
| **`latency`** | ms | Ping / ความหน่วง | **ยิ่งต่ำยิ่งดี** - การตอบสนองเร็ว<br>< 50ms: ดีเยี่ยม<br>< 100ms: ใช้ได้<br>> 150ms: ช้า |
| **`jitter`** | ms | ความแกว่งของ Ping | **ยิ่งต่ำยิ่งดี** - เน็ตเสถียร<br>สูง = เน็ตมา-หาย ส่งผลต่อ Video Call |
| **`packet_loss`** | % | แพ็กเก็ตหายระหว่างทาง | **ต้องเป็น 0%** - มากกว่า 0 = มีปัญหาร้ายแรง<br>-1 = วัดไม่ได้ (ใช้ single mode) |
| `location` | string | ตำแหน่งเซิร์ฟเวอร์ทดสอบ | สำหรับอ้างอิง |

---

### 🔍 ค่าสำคัญที่ต้องโฟกัส

#### **1. Download & Upload Speed**
- ตัวชี้วัดความเร็วพื้นฐานที่ผู้ใช้รู้สึกได้โดยตรง
- ควรเทียบกับแพ็กเกจที่จ่ายเงิน (เช่น จ่าย 100/30 Mbps ควรได้ใกล้เคียง)

#### **2. Latency (Ping)**
- สำคัญสำหรับ Gaming, Video Call, Real-time Applications
- < 50ms = ดีเยี่ยม | 50-100ms = ดี | 100-150ms = พอใช้ | > 150ms = ปัญหา

#### **3. Jitter**
- บ่งชี้ความเสถียรของเน็ต
- ต่ำ = เน็ตนิ่ง | สูง = เน็ตกระตุก (Voice/Video จะมีปัญหา)

#### **4. Packet Loss** 🚨
- **ค่าวิกฤติที่สุด** - ต้องเป็น 0% เท่านั้น
- > 0% = สัญญาณเตือนปัญหาร้ายแรง (สายขาด, อุปกรณ์เสีย, ISP มีปัญหา)
- ต้องใช้ `test_mode = "multi"` เพื่อวัดค่านี้

---

### 📊 Use Cases
- **ISP SLA Monitoring**: ตรวจสอบว่า ISP ให้บริการตามที่จ่ายเงินหรือไม่
- **Network Baseline**: สร้าง baseline ความเร็วเพื่อเปรียบเทียบย้อนหลัง
- **Incident Detection**: ตรวจจับปัญหาคุณภาพเน็ตก่อนผู้ใช้แจ้ง
- **Capacity Planning**: วางแผนอัพเกรดแพ็กเกจตามการใช้งานจริง
- **Remote Site Monitoring**: ติดตามคุณภาพเน็ตของสาขา/Remote Office

---

### ⚠️ ข้อควรระวัง

1. **Bandwidth Usage**: แต่ละครั้งใช้เน็ต 10-100+ MB ขึ้นกับความเร็ว
2. **Interval Setting**: ห้ามตั้งต่ำกว่า 30 นาที (แนะนำ 1-4 ชั่วโมง)
3. **Test Mode**: ใช้ `multi` เพื่อความแม่นยำ แต่กินทรัพยากรมากกว่า
4. **Memory Saving Mode**: เปิดถ้าเครื่องแรมน้อย แต่ความแม่นยำจะลดลง (โดยเฉพาะเน็ต > 30Mbps)
